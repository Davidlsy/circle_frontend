## 一、功能概述

### 1.1 背景

后端已实现第三方账号（微信/抖音/支付宝）的注册、登录、绑定、解绑功能。**注册与登录为两个独立接口**，需前端分别实现：

- **注册**：用户首次通过第三方账号创建本站账号
- **登录**：已注册或已绑定第三方账号的用户通过第三方账号登录

### 1.2 核心规则

> ⚠️ 重要：登录接口不会自动注册，未注册/未绑定的第三方账号无法登录

| 场景 | 调用接口 | 结果 |
|------|---------|------|
| 首次使用第三方账号 | `/register` | 创建账号 + 登录 |
| 已注册的第三方账号登录 | `/callback` | 登录成功 |
| 已绑定第三方账号的本站用户登录 | `/callback` | 登录成功 |
| 未注册/未绑定的第三方账号尝试登录 | `/callback` | **400 错误** |

### 1.3 支持的第三方平台

| 平台 | provider 值 | Mock 模式 | 真实模式 |
|------|------------|-----------|----------|
| 微信 | `wechat` | ✅ 支持 | 需配置 WECHAT_CLIENT_ID |
| 抖音 | `douyin` | ✅ 支持 | 需配置 DOUYIN_CLIENT_ID |
| 支付宝 | `alipay` | ✅ 支持 | 需配置 ALIPAY_APP_ID |

> 开发阶段建议使用 Mock 模式（`OAUTH_MOCK_MODE=true`），无需真实凭证即可联调。

## 三、核心接口详解

### 3.1 获取授权 URL

**请求**

```
GET /auth/oauth/{provider}/authorize?purpose=login
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `provider` | path | 是 | `wechat` / `douyin` / `alipay` |
| `purpose` | query | 否 | `login`（默认）/ `bind` |

**响应**

```json
{
  "authorize_url": "https://...",
  "state": "随机字符串（由后端生成）",
  "provider": "wechat"
}
```

**前端逻辑**

1. 用户点击"微信注册"或"微信登录"按钮
2. 调用此接口获取 `authorize_url` 和 `state`
3. 保存 `state` 到本地（localStorage 或 Vuex/Pinia）
4. `window.location.href = authorize_url` 跳转到第三方授权页

---

### 3.2 第三方账号注册（核心新增）

**请求**

```
POST /auth/oauth/{provider}/register
Content-Type: application/json

{
  "code": "第三方回调返回的授权码",
  "state": "授权时返回的 state",
  "username": "可选，用户自定义用户名"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | string | 是 | 授权码，长度 1-500 |
| `state` | string | 是 | CSRF 防护 state，长度 1-200 |
| `username` | string | 否 | 用户自定义用户名，长度 1-50。不传则自动生成 `{provider}_{nickname}` |

**响应（成功）**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "is_new_user": true
}
```

| 字段 | 说明 |
|------|------|
| `access_token` | JWT 令牌，前端需存储 |
| `token_type` | 固定 `bearer` |
| `is_new_user` | `true`=新注册成功；`false`=该第三方账号已存在，直接登录 |

**错误响应**

| 状态码 | 错误信息 | 处理建议 |
|--------|---------|----------|
| 400 | `用户名已被使用` | 提示用户更换用户名 |
| 400 | `State 校验失败...` | state 过期或被篡改，重新发起授权 |
| 400 | `Mock 授权码已过期...` | Mock 模式下授权码 5 分钟过期 |
| 502 | `第三方服务暂时不可用` | 真实模式下第三方接口异常 |

**前端逻辑**

1. 用户点击注册按钮 → 调用 `/authorize` 获取授权 URL
2. 跳转授权页 → 用户授权 → 回调到前端
3. 前端从 URL 参数提取 `code` 和 `state`
4. **可选**：弹出"输入用户名"对话框，让用户自定义用户名
5. 调用 `/register` 接口
6. 成功 → 存储 `access_token`，跳转首页
7. `is_new_user=true` → 显示欢迎提示
8. `is_new_user=false` → 该第三方账号已存在，直接登录

---

### 3.3 第三方账号登录

**请求**

```
POST /auth/oauth/{provider}/callback
Content-Type: application/json

{
  "code": "第三方回调返回的授权码",
  "state": "授权时返回的 state"
}
```

**响应（成功）**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer"
}
```

> 注意：登录接口响应**不含** `is_new_user` 字段

**错误响应（关键）**

| 状态码 | 错误信息 | 处理建议 |
|--------|---------|----------|
| 400 | `该{平台}账号未注册或未绑定本站账号，请先注册或绑定` | **引导用户去注册页或登录本站账号后绑定** |
| 400 | `State 校验失败...` | 重新发起授权 |
| 502 | `第三方服务暂时不可用` | 真实模式下第三方接口异常 |

**前端逻辑**

1. 用户点击登录按钮 → 调用 `/authorize` 获取授权 URL
2. 跳转授权页 → 用户授权 → 回调到前端
3. 前端从 URL 参数提取 `code` 和 `state`
4. 调用 `/callback` 接口
5. 成功 → 存储 `access_token`，跳转首页
6. **400 错误（未注册/未绑定）** → 弹窗提示并提供两个选项：
   - "去注册" → 跳转注册页
   - "用本站账号登录后绑定" → 跳转本站登录页

## 四、Mock 模式对接说明

### 4.1 Mock 模式价值

开发阶段无需真实第三方凭证，后端 Mock 模式提供：
- 本地 Mock 授权页（HTML）
- 预设测试账号（每个平台 2 个）
- 模拟授权码生成与解析

### 4.2 Mock 测试账号

调用 `GET /mock/oauth/{provider}/accounts` 获取：

```json
{
  "provider": "wechat",
  "accounts": [
    { "oauth_uid": "mock_wechat_openid_001", "nickname": "测试微信用户A", "avatar": "..." },
    { "oauth_uid": "mock_wechat_openid_002", "nickname": "测试微信用户B", "avatar": "..." }
  ]
}
```

### 4.3 Mock 授权流程

1. 调用 `/auth/oauth/wechat/authorize` → 返回 Mock 授权页 URL
2. 跳转到 Mock 授权页（后端内置 HTML）
3. 用户在 Mock 页选择测试账号 → 生成 `mock_code`
4. Mock 页自动跳转回前端回调页，携带 `code` 和 `state`
5. 前端按正常流程调用 `/register` 或 `/callback`

### 4.4 Mock 授权码格式

```
mock_{provider}_{account_index}_{timestamp}
```

例如：`mock_wechat_1_1780000000`

> 时效 5 分钟，过期需重新授权

### 5.4 OAuth 回调页

**路径**：`/oauth/callback/{provider}`

**职责**：
- 从 URL 参数提取 `code` 和 `state`
- 校验 state 与本地存储一致
- 根据 `oauth_action` 调用不同接口
- 处理成功/失败响应

**实现示例**：

```javascript
// /oauth/callback/:provider 页面
async function handleOAuthCallback() {
  const provider = getProviderFromRoute();  // wechat / douyin / alipay
  const code = new URLSearchParams(window.location.search).get('code');
  const state = new URLSearchParams(window.location.search).get('state');

  // 校验 state
  const savedState = localStorage.getItem('oauth_state');
  if (state !== savedState) {
    showError('State 校验失败，可能存在安全风险');
    return;
  }

  const action = localStorage.getItem('oauth_action');  // login / register

  try {
    let resp;
    if (action === 'register') {
      // 可选：弹出用户名输入框
      const username = await promptUsername();
      resp = await fetch(`/auth/oauth/${provider}/register`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ code, state, username })
      });
    } else {
      resp = await fetch(`/auth/oauth/${provider}/callback`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ code, state })
      });
    }

    if (resp.ok) {
      const data = await resp.json();
      // 存储 token
      localStorage.setItem('access_token', data.access_token);
      // 清理临时数据
      localStorage.removeItem('oauth_state');
      localStorage.removeItem('oauth_action');

      if (action === 'register' && data.is_new_user) {
        showWelcome('注册成功，欢迎加入！');
      }
      // 跳转首页
      router.push('/');
    } else {
      const err = await resp.json();
      handleOAuthError(resp.status, err.detail, action);
    }
  } catch (e) {
    showError('网络错误，请重试');
  }
}

function handleOAuthError(status, detail, action) {
  if (status === 400 && detail.includes('未注册或未绑定')) {
    // 登录时发现未注册 → 提供选项
    showConfirm(
      '该第三方账号尚未注册，是否前往注册？',
      () => router.push('/register'),
      () => router.push('/login')
    );
  } else if (status === 400 && detail.includes('用户名已被使用')) {
    showError('用户名已被使用，请更换');
  } else {
    showError(detail || '操作失败，请重试');
  }
}
```

## 六、Token 管理

### 6.1 存储方式

- **access_token**：存储于 localStorage（Web）或 AsyncStorage（移动端）
- **统一 Header**：所有需认证的请求携带 `Authorization: Bearer <token>`

### 6.2 axios 拦截器配置

```javascript
// 请求拦截器
axios.interceptors.request.use(config => {
  const token = localStorage.getItem('access_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// 响应拦截器
axios.interceptors.response.use(
  response => response,
  error => {
    if (error.response?.status === 401) {
      // token 失效
      localStorage.removeItem('access_token');
      router.push('/login');
    }
    return Promise.reject(error);
  }
);
```

| 400 | 重复绑定 | `您已绑定了 {平台} 账号，请先解绑` | 提示先解绑 |
| 400 | 第三方账号被占用 | `该第三方账号已被其他用户绑定` | 提示账号已被占用 |
| 404 | 解绑未绑定 | `未绑定 {平台} 账号` | 刷新绑定列表 |
| 401 | token 失效 | `未授权` | 清除 token，跳转登录 |
| 502 | 第三方服务异常 | `第三方服务暂时不可用，请稍后重试` | 提示稍后重试 |

## 十、注意事项

1. **state 校验**：前端应在回调页校验 URL 中的 `state` 与本地存储一致，防止 CSRF
2. **action 区分**：注册和登录共用同一个授权 URL，前端需用 `localStorage` 记录当前 action
3. **Mock 模式判断**：开发环境后端默认开启 Mock，前端无需特殊处理，授权 URL 会自动指向 Mock 页
4. **用户名可选**：注册时 `username` 为可选字段，不传则后端自动生成
5. **token 时效**：JWT 默认 7 天有效期，前端无需主动刷新
6. **回调地址**：OAuth 回调页路径必须与后端 `OAUTH_FRONTEND_URL` 配置一致（默认 `http://localhost:5173`）
7. **错误处理**：登录接口返回 400 且包含"未注册或未绑定"时，应提供"去注册"选项
8. **重复注册保护**：注册接口若检测到第三方账号已存在，会直接返回登录 token（`is_new_user=false`），不会报错
9. **绑定限制**：同一第三方账号只能绑定一个本站用户；同一本站用户每个平台只能绑定一个第三方账号
10. **后端仓库**：前端联调时建议克隆后端仓库本地运行，便于排查问题：<https://github.com/Davidlsy/circle_backend>
